# Backend: AGENTS

## Stack
- Python 3.14 (Docker base image `python:3.14-slim`)
- FastAPI + uvicorn
- pydantic v2
- psycopg (binary + pool) for Postgres
- valkey (valkey-py) for session storage; valkey 8 server in compose
- bcrypt for password hashing
- pytest using FastAPI's `TestClient`; `testcontainers[postgresql,valkey]` for real infra
- pyarrow (dev-only) for the one-time seed-data vendoring script

## Layout
- `app/main.py`: FastAPI app. Lifespan creates the Postgres pool and the Valkey client, runs `ensure_schema`, `ensure_seed_admin`, and `ensure_seed_properties` (only when the DB is reachable — failures are logged and skipped so the app can still report `db=down`), and closes both on shutdown. Routes: `GET /api/health`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`, the property CRUD routes under `/api/properties`, the authed chat routes under `/api/chat`, and the unauthenticated public chat route at `POST /public/ai-chat`. Health response shape: `{"status": "ok", "database_url_set": bool, "db": "ok"|"down"?, "db_error": str?, "valkey": "ok"|"down"?, "valkey_error": str?}` — the `valkey` fields are present only when `VALKEY_URL` is set.
- `app/db.py`: `make_pool(conninfo)` builds a `psycopg_pool.ConnectionPool` (created with `open=False`, then `pool.open()` is called so connections are opened lazily on first borrow); `probe(pool, *, timeout=2.0)` runs `SELECT 1` through the pool and returns `(ok, error_message)`.
- `app/valkey_client.py`: `make_valkey(url)` builds a `valkey.Valkey.from_url(url, decode_responses=True, socket_timeout=2.0)` so values come back as `str`; `probe(client, *, timeout=2.0)` calls `PING` and returns `(ok, error_message)`.
- `app/settings.py`: single, deliberate env loader. All `os.environ` reads happen here via `get_settings()`; do not sprinkle reads across handlers. Keys: `DATABASE_URL`, `VALKEY_URL`, `AUTH_TOKEN_TTL_SECONDS` (default `86400`), `AUTH_BCRYPT_ROUNDS` (default `12`), `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`, `SEED_PROPERTIES` (default `0`; set to `1` to enable property seed on startup), `SEED_PROPERTIES_PATH` (optional override of the vendored JSON path; default `app/seed_data/properties.json`), `LLM_BASE_URL` (default `http://localhost:1234/v1`), `LLM_API_KEY` (default `not-needed` — no Authorization header is sent), `LLM_MODEL` (default `local-model` — a placeholder accepted by most OpenAI-compatible servers; for the local llama.cpp instance on `localhost:1234` the real id is `unsloth/gemma-4-12b-it-GGUF:UD-Q4_K_XL`), `LLM_TIMEOUT_SECONDS` (default `60`), `LLM_MAX_HISTORY_MESSAGES` (default `40`), `LLM_MAX_INPUT_CHARS` (default `4000`), `LLM_SYSTEM_PROMPT` (default a short real-estate assistant prompt).
- `app/migrations.py`: `SCHEMA_STATEMENTS` (tuple of idempotent DDL) and `ensure_schema(conn)` run inside a single transaction at lifespan startup. Today: the `app_user` and `property` tables.
- `app/seed.py`: `ensure_seed_admin(settings, pool)` — if `SEED_ADMIN_EMAIL` and `SEED_ADMIN_PASSWORD` are both set and `app_user` is empty, inserts one row with `role='ADMIN'`. Idempotent. `ensure_seed_properties(settings, pool)` — if `SEED_PROPERTIES=1` and `property` is empty, bulk-inserts the vendored JSON; idempotent. The vendored seed file path defaults to `app/seed_data/properties.json` (see `app/seed_data/ATTRIBUTION.md` for license and source).
- `app/auth/`: subpackage for auth.
  - `app/auth/roles.py`: `ROLE_ADMIN = "ADMIN"`. Single source of truth for the role literal. When a second role appears, replace with a `Role(StrEnum)` and switch `UserOut.role` to `Literal[...]` — no SQL migration of the `role` column.
  - `app/auth/security.py`: `hash_password`, `verify_password` (bcrypt), `new_token` (`secrets.token_urlsafe(32)`), `session_key(token)` (`sess:{token}`).
  - `app/auth/schemas.py`: pydantic v2 models — `LoginRequest` (email is normalized to lowercase + validated with a regex; password `min_length=1`, `max_length=72` to honor bcrypt 5.0.0's 72-byte limit), `UserOut`, `LoginResponse`.
  - `app/auth/routes.py`: APIRouter mounted at `/api/auth`. Login inserts `sess:{token} -> user_id` in Valkey with TTL = `AUTH_TOKEN_TTL_SECONDS`. `get_current_user` is a reusable dependency that reads the bearer token, looks up the session in Valkey, and loads the user from Postgres. Logout goes through `get_current_user` so an already-revoked token returns 401.
  - `app/auth/deps.py`: `require_admin(user: UserOut = Depends(get_current_user))` — returns 403 if `user.role != ROLE_ADMIN`. Used by all property routes.
- `app/properties/`: subpackage for property CRUD (ADMIN-only).
  - `app/properties/schemas.py`: pydantic v2 models — `PropertyType` / `ListingType` / `PropertyStatus` `StrEnum`s, `PropertyImageIn`/`Out`, `PropertyCreate`, `PropertyUpdate`, `PropertyOut`, `PropertyListItem`, `PropertyList`. String fields like `price_currency`, `country_code` are uppercased; `title`/`city`/`address_line` are trimmed; `amenities` are lowercased, trimmed, and deduped. `HttpUrl` is used for image URLs.
  - `app/properties/repository.py`: psycopg queries — `create_property`, `get_property`, `list_properties` (filters: `city`, `listing_type`, `property_type`, `status`, `min_price`, `max_price`, `bedrooms`, `q` text search on title+description; paged via `limit`/`offset`; ordered by `created_at DESC, id DESC`), `update_property` (only columns present in `exclude_unset=True` payload), `delete_property` (hard delete).
  - `app/properties/routes.py`: APIRouter mounted at `/api/properties`. `POST` and `GET /` create and list; `GET /{id}`, `PATCH /{id}`, `DELETE /{id}` for one record. All routes depend on `require_admin`. `DELETE` is a hard delete (no soft-delete / `ARCHIVED` status).
- `app/chat/`: subpackage for the LLM-backed chat assistant. Any authenticated user can use it (not admin-only). Owns two tables — `chat_conversation` (FK to `app_user` ON DELETE CASCADE) and `chat_message` (FK to `chat_conversation` ON DELETE CASCADE, `role` `CHECK IN ('system','user','assistant')`). Schema and indexes are in `app/migrations.py`.
  - `app/chat/schemas.py`: pydantic v2 — `ChatRole` `StrEnum` (`system` / `user` / `assistant`), `ChatMessageCreate`/`Out`, `ChatConversationCreate`/`Summary`/`List`/`Out`, `SendMessageResponse`.
  - `app/chat/repository.py`: psycopg — `create_conversation`, `get_conversation_owned` (joins + ownership filter; returns `None` when missing or not owned), `list_conversations` (with `message_count` subquery; ordered by `updated_at DESC, id DESC`), `append_message`, `load_history` (newest-first cap, then re-ordered chronologically), `touch_conversation` (bumps `updated_at = NOW()`), `delete_conversation` (hard delete cascades to messages). Every query is scoped by `user_id`.
  - `app/chat/llm.py`: `complete(messages, *, settings=None, client=None)` — POSTs to `{LLM_BASE_URL}/chat/completions` via `httpx.Client` (sync), no streaming, returns the assistant `content` string, raises typed `LLMError` on non-2xx / malformed / empty-content responses. Sends `Authorization: Bearer ...` only when `LLM_API_KEY` is set to something other than the default `not-needed` placeholder. The HTTP client is injectable for tests. The response envelope follows the OpenAI chat-completions shape; for reasoning-capable models `message` may carry both `content` (the reply we persist) and `reasoning_content` (chain-of-thought we ignore). Tool/function-call responses are not yet supported and surface as `LLMError("LLM returned empty content")`.
  - `app/chat/service.py`: orchestrates one turn — verifies ownership, inserts the user message, loads capped history, prepends the system prompt, calls `llm.complete`, inserts the assistant reply, bumps `updated_at`. Raises `ConversationNotFoundError` and `ValueError` (oversize content) which the routes translate to 404 / 400. `LLMError` propagates to a 502.
  - `app/chat/routes.py`: APIRouter mounted at `/api/chat`. `POST /conversations`, `GET /conversations?limit=&offset=`, `GET /conversations/{id}`, `DELETE /conversations/{id}`, `POST /conversations/{id}/messages`. All routes use `get_current_user`; ownership is enforced in the repository layer (no per-route 403 — cross-user access returns 404 to avoid leaking existence). The LLM HTTP error surfaces as 502. Tool/function calling is intentionally not implemented yet.
- `app/public_chat/`: subpackage for the unauthenticated public AI chat demo at `/public/ai-chat`. No auth — anyone can use it. State is keyed by an opaque random UUID minted server-side and stored client-side in `localStorage`; on a new turn the client sends `{chat_id?, content}` and the server either creates a new session or appends to the existing one.
  - `app/public_chat/schemas.py`: pydantic v2 — `PublicChatRole` `StrEnum`, `PublicChatMessageOut`, `PublicChatSendRequest` (`chat_id: str | None` validated as UUID, `content: str` with `min_length=1, max_length=4000`), `PublicChatSendResponse` (`chat_id, user_message, assistant_message`), `PublicChatSessionOut`.
  - `app/public_chat/repository.py`: psycopg — `create_session` (mints UUID), `get_session` (404 when missing), `append_message`, `load_history` (newest-first cap, then chronological), `touch_session` (`last_active_at = NOW()`), `delete_session` (hard delete cascades to messages). No per-user filter — the client owns the chat_id.
  - `app/public_chat/routes.py`: APIRouter at `/public/ai-chat`. `POST ""` (create-or-append a turn), `GET "/{chat_id}"` (read full history), `DELETE "/{chat_id}"` (forget a session). On LLM failure the 502 detail carries `{"message": ..., "chat_id": ...}` so the client can keep the session and retry the next turn — the user message is persisted before the LLM call so the failed turn's history isn't lost.
- **RBAC policy**: no SQL-level role enforcement (no `CHECK` constraints, no row-level security, no trigger guards). Authorization is the `require_admin` Python dependency in `app/auth/deps.py`.
- `app/seed_data/`: vendored seed data + license attribution. `properties.json` is a 250-row sample adapted from `Sekirkallc/ai-data-factory-real-estate` (Hugging Face, MIT). Because the HF source is Florida-only synthetic, the vendor script deterministically overrides `city`, `district`, `country_code`, `latitude`, `longitude`, `status`, `address_line`, and `amenities` on each row from a curated 15-city US metros list so the seed has multi-city / multi-state variety for demos. See `app/seed_data/ATTRIBUTION.md` for the source, license, image-placeholder notes, and the city-synthesis details.
- `scripts/vendor_property_seed.py`: one-off offline script that downloads HF parquet snapshots (with cache fallback), samples 250 rows, normalizes them into our schema, and writes `app/seed_data/properties.json`. Run manually when the source dataset changes; **not** invoked at startup or test time. Requires `pyarrow` (dev dep).
- `tests/conftest.py`: pytest fixtures — `postgres_container` (session, `postgres:18`), `valkey_container` (session, `valkey/valkey:8`), `client_with_postgres` (function, DB only), `client_with_full_stack` (function, DB + Valkey + seed env), `db_pool_seeded` (function, gives direct pool access after migrations + seed run), `secondary_user` / `non_admin_token` (for RBAC tests), `admin_token`, `property_create_payload`. Test seed credentials are `admin@example.com` / `correct-horse-battery-staple` (constants in `conftest.py`).
- `tests/test_health.py`: health endpoint tests, all real infra, no mocks.
- `tests/test_auth.py`: login / logout / me tests against real Postgres + Valkey, plus a direct-DB test for the seed role.
- `tests/test_properties.py`: property CRUD tests — auth gating (401 / 403), create→list→get→update→delete round trip, filter+pagination, validation, hard delete, image round trip.
- `tests/test_seed_properties.py`: `ensure_seed_properties` tests — insert, idempotency, disabled-noop, missing-file warning.
- `tests/test_chat.py`: chat end-to-end tests against real Postgres + Valkey, with `app.chat.llm.complete` monkeypatched so no real LLM is contacted. Covers auth gating (401), conversation CRUD, message persistence, history accumulation, system-prompt injection, ownership isolation across two non-admin users (`non_admin_token` + `chat_other_token`), content-size validation (empty → 422, over-cap → 400), and LLM failure → 502 with no orphan assistant row.
- `tests/test_public_chat.py`: end-to-end tests for `/public/ai-chat` against the full stack (no auth), with the LLM transport monkeypatched to a `httpx.MockTransport` returning real-shape llama.cpp payloads. Covers session creation on first turn, chat_id reuse on subsequent turns, history loading (system + prior turns), `GET /{chat_id}` and `DELETE /{chat_id}`, UUID validation, `reasoning_content` being ignored, unauthenticated access, content validation, and LLM failure → 502 (with the new chat_id preserved so the client can retry).
- `requirements.txt`: production deps (`fastapi`, `uvicorn[standard]`, `pydantic`, `psycopg[binary,pool]`, `valkey`, `bcrypt`, `httpx`).
- `requirements-dev.txt`: test-only deps; chains `-r requirements.txt`.
- `run.py`: local dev entrypoint: `uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload`.
- `Dockerfile`: runs `uvicorn app.main:app --host 0.0.0.0 --port 8000` on port 8000.
- `.venv/`: already created locally; safe to reuse.

## Common Commands (run from `backend/`)
- Install deps (dev/test): `pip install -r requirements-dev.txt` (or use the existing `.venv`).
- Install deps (production-style, no test deps): `pip install -r requirements.txt`.
- Dev server: `python run.py` (or `uvicorn app.main:app --reload`). Set `SEED_PROPERTIES=1` in the environment to bulk-load the 250-row vendored seed on first start.
- All tests: `pytest` (requires a reachable Docker daemon for the testcontainers-based tests; those tests skip cleanly otherwise).
- Single test: `pytest tests/test_health.py -k <name>` (or `tests/test_auth.py`, `tests/test_properties.py`, `tests/test_seed_properties.py`).
- Re-vendor seed data (rare): `.venv/bin/python scripts/vendor_property_seed.py`. Downloads HF parquet snapshots into `.cache/seed-vendor/` and writes `app/seed_data/properties.json`.

## Docker
From the repo root: `docker compose up --build`. Three services: `db` (postgres:18), `valkey` (valkey/valkey:8), `backend`. `db` exposes `5432:5432` (dev only — change before deploying), has a `pg_isready` healthcheck, and persists to the `postgres_data` volume. `valkey` exposes `6379:6379`, has a `valkey-cli ping` healthcheck, and persists to the `valkey_data` volume. `backend` binds `8000:8000`, receives `DATABASE_URL`, `VALKEY_URL`, and the LLM env (`LLM_BASE_URL` defaulting to `http://localhost:1234/v1` to match `app/settings.py`; plus `LLM_API_KEY`, `LLM_MODEL`, `LLM_TIMEOUT_SECONDS`) from compose, references `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` / `SEED_PROPERTIES` from the host environment (resolved from the gitignored `.env` at the repo root — see Workflow Rules), waits for both `db` and `valkey` to be healthy, and rebuilds on changes under `./backend`. DB and seed credentials in `compose.yaml` are dev-only.

**Note on `LLM_BASE_URL` in compose**: the backend container's own loopback is NOT the host's. The default `http://localhost:1234/v1` only works for host-side dev (`python run.py`); under `docker compose` you must override `LLM_BASE_URL` to reach a host-side model server. Options are documented inline in `compose.yaml` — Docker Desktop can use `http://host.docker.internal:1234/v1`, Linux Docker bridge users need the bridge gateway IP (e.g. `http://172.20.0.1:1234/v1`, verify with `docker network inspect`), or run the model as a compose service.

## Workflow Rules
- **Dependencies**: before adding or bumping anything in `requirements.txt` or `requirements-dev.txt`, look up the latest stable version on the web (PyPI / the package's official docs) and ask the user before editing the file. Do not silently pin a version you have not verified.
- **Verify with tests**: after any implementation change, run `pytest` from `backend/` and make sure it passes. Prefer adding or updating a test alongside the code change.
- **Env vars**: `.env` is gitignored at the repo root. Env loading lives in `app/settings.py` via `get_settings()`; add new config there rather than sprinkling `os.environ` reads across handlers.
- **Session store**: Valkey only. Keys are `sess:{token}` → `user_id` (str). No `app_user_session` Postgres table; sessions are not in SQL.
- **Password hashing**: bcrypt 5.x. The 72-byte limit is enforced at the pydantic layer (`LoginRequest.password` `max_length=72`). If longer passwords ever need support, pre-hash with SHA-256 + base64 before bcrypt (per the bcrypt docs).
- **Property images**: stored in the `property.images` JSONB column. The vendored seed uses Picsum placeholder URLs (CC0); the admin CRUD path validates each URL with pydantic `HttpUrl`. No binary uploads in the MVP.
- **Property delete is hard**: `DELETE /api/properties/{id}` removes the row. There is no `ARCHIVED` status; the `status` enum is `AVAILABLE` / `RESERVED` / `SOLD` / `RENTED`.
